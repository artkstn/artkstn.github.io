# MISTAKES

Журнал ошибок и их причин. Формат и правила ведения — в CLAUDE.md
(раздел «Ведение журналов изменений и ошибок»). Перед началом значимой задачи
проверяй этот файл на релевантные записи.

## [2026-09-23] Модалка резюме на кейсах через fetch — лишний компромисс
- Чтобы не дублировать длинный текст резюме в четырёх файлах, сделал модалку резюме
  на страницах кейсов через `fetch('../cv-modal.html')` вместо инлайн-разметки, и
  явно предупредил, что из-за этого CV не откроется при открытии страницы напрямую
  из файловой системы (`file://`). Пользователь сказал прямо: нужно, чтобы работало
  везде без оговорок — и вариант с fetch пришлось откатить на полное дублирование
- Почему это произошло: сам придумал компромисс (экономия на дублировании текста)
  и молча выбрал его как решение по умолчанию, вместо того чтобы сначала спросить,
  насколько для пользователя важна работа через `file://`. Предупреждение в ответе
  не заменяет вопрос до реализации — я сообщил о трейд-оффе постфактум, когда его
  уже было дороже переделывать
- Что делать иначе: если для решения задачи есть путь без рисков (здесь — обычное
  дублирование HTML, ничем не хуже уже принятой в проекте практики дублировать
  index.html/styles.css) и путь с компромиссом ради чистоты кода (fetch, экономия
  строк) — по умолчанию выбирать путь без рисков для пользовательского сценария,
  особенно на живом продакшн-сайте. «Технически элегантнее» — не повод жертвовать
  надёжностью там, где дублирование не создаёт реальной проблемы

## [2026-09-22] Рамка вокруг кнопки CV в Safari
- При замене ссылки «CV» на `<button class="action" data-cv-open>` в Safari вокруг
  кнопки была видна лишняя дуга/тень — артефакт нативного рендеринга кнопки
- Причина: в базовом ресете сайта не было `appearance: none` для `<button>` (только
  `border: 0` точечно у `.theme-toggle`/`.cv-close`). Пока все кнопки-триггеры были
  `<a>`, это не проявлялось — у ссылок нет нативного chrome. Первый же `<button>`,
  стилизованный классом `.action` без собственного `border`, вскрыл пробел в ресете
- Что делать иначе: при добавлении любого нового `<button>` в проект сразу проверять
  базовый ресет (`appearance`, `border`, `background`) вместо точечных стилей на
  конкретном классе — и проверять в Safari/WebKit, а не только в Chromium, для
  элементов форм (button/input/select), у которых нативный chrome разный по движкам

## [2026-09-22] Крестик закрытия модалки — кривой глиф и «прыжки» на мобильном
- Иконка крестика была текстовым символом `&#10005;` (✕) в круглой кнопке — в разных
  шрифтах/браузерах он визуально не центрируется идеально, выглядит «кривым».
  Отдельно кнопка была позиционирована `position: fixed` с привязкой к
  `env(safe-area-inset-top)`, то есть к вьюпорту, а не к карточке модалки —
  на iOS Safari при скролле внутри модалки браузер анимированно
  скрывает/показывает адресную строку, из-за чего высота вьюпорта и
  safe-area-inset пересчитываются на лету, и `position: fixed`-элемент визуально
  дёргается независимо от самой карточки
- Причина: не подумал, что элемент, который должен «жить» вместе с конкретной
  карточкой (двигаться, скрываться, скроллиться с ней как единое целое), нельзя
  позиционировать через `position: fixed` относительно вьюпорта — только `absolute`
  относительно самой карточки. А для иконок closeicon текстовый глиф — плохая
  замена SVG: центрирование зависит от метрик шрифта, которые не гарантированы
- Что делать иначе: для мелких UI-иконок (крестик, стрелка, галочка) всегда
  использовать inline SVG с `stroke="currentColor"`, а не символ шрифта. Элемент,
  который визуально должен быть частью карточки/панели — позиционировать
  `absolute` внутри неё, а не `fixed` к вьюпорту, даже если кажется, что это
  «тот же угол экрана»; на мобильном Safari разница проявляется при скролле
