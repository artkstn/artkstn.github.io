# Портфолио-сайт (artkstn.github.io)

## О проекте
Личный сайт-портфолио, размещён на GitHub Pages по адресу https://artkstn.github.io
(user/org page — репозиторий называется `artkstn.github.io`, поэтому base path = `/`,
никакого префикса вроде `/game/` нет и быть не должно).

## Стек
Чистый HTML/CSS/JS, без сборщика и фреймворка. Главная страница — один файл `index.html`
(разметка, `<style>` и `<script>` инлайн внутри него, самодостаточный). Страницы кейсов
в `cases/` подключают общие `styles.css` и `script.js` (см. «Структура проекта») —
дублировать их вёрстку/логику по кейсам было бы хуже, чем один раз синхронизировать
токены между index.html и styles.css. Зависимостей и `package.json` нет.

## Деплой на GitHub Pages
- Публикуется напрямую из корня ветки `main` (стандартное поведение для репозитория
  `<user>.github.io`), без GitHub Actions и без промежуточной сборки.
- Все ссылки на ассеты и внутренние переходы — относительные пути или пути от корня
  (`/...`), без каких-либо префиксов base path.
- Отдельного шага `build`/`preview` не требуется: что лежит в `index.html` на `main`,
  то и отдаётся сайтом один в один. Перед пушем в `main` — открыть файл в браузере
  локально и проверить, что ничего не сломано.
- `.github/workflows/` в репозитории нет; если он появится — не менять без явного
  запроса пользователя (деплой — видимое всем действие).

## Структура проекта
- `index.html` — главная: `<head>` с метатегами/JSON-LD, `<style>` с токенами и
  адаптивом, разметка секций (`hero`, `projects`), `<script>` в конце `body` с логикой
  темы, клиентским хранилищем (`localStorage`, ключ `portfolio.state`),
  IntersectionObserver для анимации появления блоков и модалкой резюме.
- `cases/` — страницы отдельных кейсов (например `cases/betest.html`), каждая — шаблон
  «шапка с кейсом → обложка → блоки текста → результат → следующий кейс», подключает
  `../styles.css` и `../script.js`. Открываются по клику с карточек на главной.
- `styles.css`, `script.js` — общие для страниц в `cases/`: токены/сброс/карточки/модалка
  резюме продублированы из `index.html` (там они инлайн по конвенции — см. «Стек»),
  `script.js` — тема, появление блоков при прокрутке и логика модалки резюме.
- Модалка резюме продублирована как есть (весь текст) в конце `<body>` каждого файла
  в `cases/` — так же, как в `index.html`, без fetch/подгрузки партиалов, чтобы кнопка
  CV работала везде одинаково, включая открытие страницы напрямую из файловой системы
  (`file://`). Правишь текст резюме — обнови все четыре места: `index.html` и три файла
  в `cases/`.
- Карточки проекта на главной бывают активными (`<a class="card">`, ведут на страницу
  в `cases/`) и неактивными (`<div class="card card--soon">` с тегом «Скоро» — кейс ещё
  не описан). См. комментарий над карточками в `index.html`.
- `img/` — статика (сейчас только `portrait.jpg`), `files/` — скачиваемые документы
  (PDF резюме). Превью самих кейсов пока плейсхолдеры (`.card__ph`), картинки под них
  ещё не готовы.

## Конвенции
- Коммиты: свободный стиль, короткое описание сути на русском (см. историю:
  «Добавить портфолио-страницу»), без обязательного Conventional Commits.
- Ветки: работа ведётся в отдельных ветках (например `claude/...`), `main` — то, что
  задеплоено или готово к деплою.
- Сборочных артефактов нет в принципе (нет шага сборки), поэтому и коммитить нечего.

## Ведение журналов изменений и ошибок

### CHANGELOG.md — крупные изменения
После любого значимого изменения (новая фича, смена архитектуры/стека, изменение
деплоя, breaking change в структуре) — добавляй запись в CHANGELOG.md в формате:

```
## [Дата]
- Что изменилось (коротко, по делу)
- Почему (если не очевидно из diff)
```

Не логируй мелкие правки (опечатки, форматирование, мелкий рефакторинг) — только то,
что стоит помнить через месяц.

### MISTAKES.md — ошибки и их причины
Когда допустил ошибку, которую пользователь исправил, или сам нашёл и исправил баг,
который сам же внёс — добавляй запись в MISTAKES.md:

```
## [Дата] Короткое название проблемы
- Что пошло не так
- Почему это произошло (корневая причина, не симптом)
- Что проверять/делать иначе в следующий раз
```

ПЕРЕД началом любой значимой задачи — сначала пробегись по MISTAKES.md и проверь,
нет ли релевантных записей для текущей области кода/фичи.

## Что НЕ делать без явного запроса
- Не пушить в `main` и не запускать деплой самостоятельно.
- Не менять настройки GitHub Pages репозитория (Settings → Pages).
- Не заводить `.github/workflows/` или другой CI для деплоя без подтверждения
  пользователя.
